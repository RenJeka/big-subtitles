# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Що це

«ВеликіСлова» (big-subtitles) — застосунок доступності для людей із порушеннями слуху/зору.
Помічник пише текст на телефоні (**Sender**) → текст миттєво з'являється великим шрифтом на
іншому екрані (**Display**, напр. iPad). Один статичний фронтенд, **без бекенду й БД**;
синхронізація через публічний MQTT-брокер по WebSocket. Деталі — у `README.md`,
вихідна постановка — у `spec-velyki-slova-mvp.md`. Спілкування/коміти/доки — українською.

## Запуск і перевірка

Збірки немає (статика). Тестів і лінтера немає — верифікація **ручна в браузері**.

```bash
py -m http.server 8000        # або: npx http-server -p 8000
```

- **Відкривати тільки через `http://localhost` або HTTPS, НЕ через `file://`** — код на
  ES-модулях, які браузер не вантажить з file:// (CORS).
- Сценарій перевірки (дві вкладки): вкладка A `…/?role=display` згенерує кімнату+ключ+QR;
  скопіювати посилання з-під QR (`?role=sender#room=…&k=…`) у вкладку B; друкувати в B →
  текст має з'явитися в A < 1 с. Перевіряти: Enter (зсув у історію), тему/розмір, режими
  показу (суфлер/бігучка) і швидкість, перезавантаження (кімната+ключ з localStorage),
  коротку втрату мережі (статус «перепідключення»).
- У цьому середовищі для прогону зручний Playwright MCP: дві вкладки display/sender,
  `browser_type` у `textarea#input`, читати `#live` / `#history .line` на display.

## Критичні обмеження (звіряти кожну зміну)

- **Приймач — iPad Air 2 / Safari 15.** ES-модулі ОК (Safari 11+), але **без top-level await**
  і обережно з найновішими API. Тестувати ментально під WebKit 15.
- **Українська вводиться системною клавіатурою** (Gboard/голос). НЕ використовувати Web Speech API —
  застосунок бере вже готовий текст із поля.
- **Нічого не зберігати**, крім кімнати/ключа/налаштувань у `localStorage`. Брокер публічний,
  але payload **E2E-шифрується** (AES-GCM, ключ у фрагменті URL і `localStorage`, на брокер не
  йде). Уся криптологіка — лише в `crypto.js`; не виносити її в інші модулі.
- Шрифт — **Andika** (повна кирилиця). Перед заміною шрифту перевіряти наявність кирилиці
  на Google Fonts (багато «accessibility»-шрифтів, як-от Atkinson Hyperlegible, її не мають).

## Архітектура

Один HTML, **три екрани/режими** в одному коді; режим визначає `app.js` за `?role=display|sender`,
інакше — стартовий екран із кнопками. `index.html` містить розмітку всіх трьох екранів
(`#screen-start`, `#screen-display`, `#screen-sender`) і підключає **лише точку входу**
`<script type="module" src="js/app.js">`. CDN-бібліотеки (MQTT.js, qrcodejs) — класичні
скрипти, що дають глобали `mqtt` / `QRCode` (у модулях використовуються через `typeof mqtt`).

**ES-модулі, явні `import`/`export`** (namespace-патерну `window.VS` більше немає). Шар залежностей:

- `config.js` — **усі** константи: брокер, тема MQTT, presence, ключі localStorage,
  параметри шифрування (`KEY_BYTES`/`IV_BYTES`), ліміти, debounce, ролі, типи повідомлень
  протоколу, режими показу та швидкості, параметри fit-text/QR, UI-тексти й значення за
  замовчуванням. Жодних «магічних» чисел чи рядків у решті модулів.
- `store.js` — безпечна обгортка над localStorage (`get/set` з fallback).
- `utils.js` — DOM (`$`, `show`), `makeToken` (24-симв. base62 через `crypto`), парсинг URL,
  `resolveRoom`/`saveRoom`, `setStatus`.
- `crypto.js` — **E2E-шифрування payload** (AES-GCM 256-біт через Web Crypto). Уся
  криптологіка ізольована тут: `makeKeyB64`/`initKey`/`encrypt`/`decrypt`. Текст шифрується
  у браузері перед публікацією; ключ ніколи не йде на брокер.
- `fit-text.js` — `fit()`: бінарний пошук найбільшого шрифту, що вміщається у контейнер.
- `live-view.js` — `createLiveView()`: контролер показу live-тексту за режимом
  (fit/scroll/tele/marquee). Авто-рух суфлера/бігучки — **чиста CSS-анімація** (без JS у
  циклі): JS лише раз на зміну контенту вимірює геометрію й задає CSS-змінні `--vs-*`.
- `mqtt-client.js` — `connect/encode/decode` + presence (LWT/retained-маркери). **Уся
  MQTT-специфіка ізольована тут**: заміна транспорту (власний брокер/Firebase у v2) має не
  виходити за цей файл.
- `settings.js` — тема, розмір, режим показу, швидкість, шестірня, банер автоблокування;
  `init(hooks)` приймає колбеки `onSizeChange`/`onModeChange`/`onSpeedChange`/`onShowQr`.
- `display.js` / `sender.js` — режими, кожен експортує `init()`. Sender також синхронізує
  налаштування на Display через повідомлення `settings`.
- `app.js` — точка входу, `boot()`.

**Стилі** (`css/`) розбито на логічні партіали; `css/styles.css` — **вхідна точка**, що
лише підключає їх через `@import` (дзеркало `app.js`): `base.css` (токени, reset, каркас,
утиліти), `start.css`, `components.css` (спільне: статус/тулбар/налаштування/степер),
`display.css`, `sender.css`, `qr-modal.css`. Жодних inline-стилів у `index.html`.
`?v=N` у `@import` та в `<link>` — інвалідатор кеша; бампати разом при зміні стилів.

**Протокол** (тема `velyki/<room>`, payload — base64url(iv)+`.`+ciphertext від AES-GCM
над JSON):
- `{ "type":"live", "text":"…" }` — поточний рядок, publish при кожній зміні з `retain:true`
  (debounce у sender ~150 мс; `retain` дає останній рядок тому, хто приєднався пізніше).
- `{ "type":"commit", "text":"…" }` — Enter у sender: рядок іде в історію Display, без retain.
- `{ "type":"settings", "size", "displayTheme", "mode", "speed" }` — Sender керує показом на
  Display. Publish з `retain:true` в **окрему тему `velyki/<room>/settings`** (не в тему
  кімнати!): на одну тему припадає лише один retained-payload, тож спільна тема призводила б
  до затирання retained-`settings` свіжим retained-`live`, і перезавантажений Display не
  отримував би актуальних налаштувань. Display підписується і на тему кімнати, і на тему
  налаштувань; тип повідомлення визначає вже сам обробник після дешифрування.
- **Presence**: кожна роль публікує retained-маркер у `velyki/<room>/presence/<role>` і
  стежить за партнером; LWT/закриття вкладки очищають маркер → статус «очікування пристрою…».
- Display тримає історію (останні ~10 рядків) у самому DOM (`#history`), анімуючи лише новий рядок.

**Парування:** Display генерує кімнату-токен + E2E-ключ, кладе їх у `localStorage` і
`#room=…&k=…`, показує QR із повним Sender-URL. Sender бере кімнату й ключ із фрагмента URL
(зі сканованого QR) або з `localStorage`. **Ключ несеться лише у фрагменті (`#`) — на брокер не потрапляє.**

### Як розширювати

- Новий режим/екран: секція в `index.html` + `js/<name>.js` з `export function init(){…}` +
  імпорт у `app.js` і гілка в `boot()`; стилі — окремий партіал у `css/` + `@import` у `styles.css`.
- Тримати сумісність із Safari 15 і не покладатися на `file://`.
