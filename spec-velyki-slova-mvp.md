# Специфікація MVP: «ВеликіСлова»

> Бриф для реалізації в Claude Code. Лін-версія: **без реєстрації, без бази даних, без власного бекенду.**

## Мета
Помічник друкує/диктує на телефоні (Android) → текст **великим шрифтом миттєво** на iPad бабусі. Цінність MVP — швидко зробити й показувати текст тут і зараз, у реальному часі.

## Принцип MVP
- **Один статичний HTML-файл** (відкривається з будь-якого HTTPS-хостингу: GitHub Pages / Netlify / Vercel).
- Синхронізація через **публічний MQTT-брокер по WebSocket** — без акаунтів, без БД. Напр. `wss://broker.emqx.io:8084/mqtt` або `wss://test.mosquitto.org:8081` через бібліотеку MQTT.js (підключити з CDN).
- **Жодних даних не зберігається.** Текст живе тільки під час сеансу. `retain: true` дає останній рядок тому, хто приєднався пізніше.

## Критичні обмеження
- **Приймач — iPad Air 2 / Safari 15.** Ванільний JS, без top-level await, обережно з новими API. Тестувати на WebKit 15.
- **Українська — через системну клавіатуру** (Gboard, голосовий ввід). Застосунок бере вже готовий текст із поля. НЕ покладатися на Web Speech API.
- Потрібен **інтернет + HTTPS** на обох пристроях.

## Ролі (один файл, два режими)
- **Sender (телефон):** textarea; трансляція під час набору (debounce ~150 мс); кнопка «Очистити».
- **Display (iPad):** повний екран; величезний автомасштабований текст; темний фон / світлий текст; останні ~10 рядків у пам'яті; автоскрол.

## Парування / безпека
- Room через URL-хеш: `#room=<токен>`, де токен — **довгий випадковий рядок (≥ 20 символів, base62)**. Цей токен і є єдиним захистом: непридатний для вгадування → чужі не приєднаються.
- Токен генерується на Display і передається на Sender **через QR** (вручну не вводиться, тому довжина не заважає).
- Room тримати в `localStorage` для відновлення після перезавантаження.
- Без шифрування payload (за рішенням): брокер бачить текст відкритим. Прийнятно для домашніх розмов; чутливе не передавати.

## Транспорт (MQTT-деталі)
- Тема: `velyki/<room>`.
- Sender: `publish("velyki/<room>", text, { retain: true })` при кожній зміні (debounce).
- Display: `subscribe("velyki/<room>")` → рендер.
- Авто-reconnect — вбудований у MQTT.js; показувати статус «з'єднано / перепідключення».

## Поведінка
- Sender друкує → Display оновлюється < 1 с (поточний «живий» рядок).
- Enter → рядок зсувається в історію (в пам'яті Display), поле очищається.
- Display: повзунок розміру шрифту + перемикач теми, сховані в кутку (щоб бабуся не натисла випадково).
- Підказка на Display: «Налаштування → Дисплей → Автоблокування → Ніколи», щоб екран не гас (Wake Lock на Safari 15 не працює).

## Приватність (важливо для публічного брокера)
- Брокер публічний → хто знає тему, той може читати/писати. Використовувати **випадковий room** як «секрет». Не передавати чутливі дані. Для домашніх розмов прийнятно; для приватності — у v2 перейти на свій брокер/Firebase.

## Поза рамками MVP
- Збереження історії, акаунти, БД, офлайн, розпізнавання мовлення в застосунку, двосторонній чат.

## Критерії приймання
- [ ] Текст з телефона з'являється на iPad за < 1 с.
- [ ] Працює на Safari 15 (iPad Air 2).
- [ ] Без реєстрації та без власного бекенду/БД.
- [ ] Парування через посилання/QR, room відновлюється після перезавантаження.
- [ ] Великий контрастний автомасштабований текст; перемикач теми та розміру.
- [ ] Авто-перепідключення після короткої втрати мережі.

## Стартова точка для реалізації
- `index.html` + MQTT.js з CDN + QR-бібліотека з CDN. Без бандлера, якщо синтаксис лишити сумісним з Safari 15.
- Режим визначати з URL (`?role=display` / `?role=sender`) або кнопками на старті.
