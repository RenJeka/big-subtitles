# ВеликіСлова (big-subtitles)

Застосунок для людей із порушеннями слуху та зору: помічник пише текст на телефоні —
і він **миттєво з'являється великим контрастним шрифтом** на екрані іншого пристрою
(напр. iPad бабусі) у реальному часі.

- **Статичний застосунок** (HTML + CSS + ванільний JS, без бандлера). Без реєстрації, без бази даних, без власного бекенду.
- Синхронізація через публічний MQTT-брокер по WebSocket (**EMQX**, `wss://broker.emqx.io:8084/mqtt`).
- Парування через **QR-код**: дисплей показує QR, помічник сканує його штатною камерою телефона.
- **E2E-шифрування** (AES-GCM): попри публічний брокер, текст шифрується у браузері; ключ несеться у фрагменті QR-URL і ніколи не йде на сервер.
- Дані ніде не зберігаються — текст живе лише під час сеансу.
- **Режими показу на дисплеї**: авто-розмір, прокрутка, суфлер і бігуча строка (з регулюванням швидкості); Sender може керувати ними дистанційно.

## Як користуватися

1. Відкрийте `index.html` (через HTTPS або `http://localhost`) на **обох** пристроях.
2. На iPad натисніть **«📺 Я — Дисплей»**. З'явиться QR-код і кімната збережеться в пристрої.
3. На телефоні наведіть **камеру** на QR — браузер відкриє режим **«⌨️ Я — пишу»** у тій самій кімнаті.
4. Пишіть у полі — текст з'являється на дисплеї за < 1 с.
   - **Enter** — зсуває поточний рядок в історію на дисплеї, поле очищається.
   - **«Очистити»** — стирає поточний рядок.
5. На дисплеї у правому верхньому кутку — прихована **⚙ шестірня**: розмір тексту, режим
   показу (авто-розмір / прокрутка / суфлер / бігуча строка) зі швидкістю, перемикач теми
   та повторний показ QR. Поряд — **📜 історія** (останні рядки; тап копіює рядок назад у live).
6. Помічник може керувати показом дистанційно: у налаштуваннях Sender є ті самі розмір,
   режим, швидкість і тема **дисплея** — вони надсилаються на Display повідомленням `settings`.

### Щоб екран iPad не гас
Wake Lock на Safari 15 ненадійний. Увімкніть:
**Налаштування → Дисплей та яскравість → Автоблокування → Ніколи.**

## Локальний запуск і перевірка

Камера та MQTT вимагають захищеного контексту. `http://localhost` його забезпечує:

```bash
# Python
python -m http.server 8000
# або Node
npx http-server -p 8000
```

Далі відкрийте `http://localhost:8000/` у двох вкладках:

- Вкладка A: режим **Дисплей** → згенерується кімната і QR.
- Вкладка B: скопіюйте посилання з-під QR (`?role=sender#room=…&k=…`) і відкрийте у новій вкладці →
  режим **Пишу**.
- Друкуйте в B — текст має з'явитися в A майже миттєво. Перевірте Enter, перемикач теми/розміру,
  режими показу (суфлер/бігучка) і швидкість, перезавантаження сторінки (кімната й ключ
  відновлюються), коротку втрату мережі (статус «перепідключення»).

## Приватність

Брокер **публічний**, тому payload **E2E-шифрується** (AES-GCM, 256-біт): хто бачить трафік
теми, бачить лише шифротекст. Захист тримається на двох секретах, що йдуть разом у QR —
довгому випадковому токені кімнати (24 символи) і ключі шифрування. **Ключ несеться лише у
фрагменті URL (`#…&k=`) — на брокер він ніколи не публікується** (фрагмент не йде у мережу).
Усе одно не передавайте надчутливі дані: безпека сеансу = таємність QR-посилання.

## Структура застосунку

```
index.html              # розмітка трьох екранів + підключення шрифту/стилів/скриптів
css/
  styles.css            # ВХІДНА ТОЧКА стилів — лише @import партіалів (дзеркало app.js)
  base.css              # дизайн-токени (CSS-змінні), reset, каркас екранів, утиліти
  start.css             # стартовий екран (вибір ролі)
  components.css        # спільне Display/Sender: статус, тулбар, налаштування, степер
  display.css           # режим Display: історія, live-текст, режими показу, банер автоблокування
  sender.css            # режим Sender: поле вводу, кнопки дій
  qr-modal.css          # спільний модал парування з QR
js/
  config.js             # усі константи: брокер, presence, ключі localStorage, шифрування,
                        # режими/швидкості, ліміти, debounce, ролі, типи повідомлень,
                        # параметри fit-text/QR, UI-тексти, defaults
  store.js              # безпечна обгортка над localStorage (get/set)
  utils.js              # хелпери DOM/URL, генерація токена, статус
  crypto.js             # E2E-шифрування payload (AES-GCM): makeKeyB64/initKey/encrypt/decrypt
  fit-text.js           # автомасштаб тексту (бінарний пошук розміру)
  live-view.js          # контролер показу live-тексту за режимом (fit/scroll/суфлер/бігучка)
  mqtt-client.js        # транспорт MQTT по WebSocket + протокол + presence (connect/encode/decode)
  settings.js           # тема, розмір, режим показу, швидкість, шестірня, банер автоблокування
  display.js            # режим Display: live-текст, історія, QR (init)
  sender.js             # режим Sender: textarea, debounce, Enter-commit, синхронізація налаштувань (init)
  app.js                # точка входу (type=module): визначає режим за ?role= → boot()
spec-velyki-slova-mvp.md # вихідна специфікація MVP
```

Код організовано як **ES-модулі** (`import`/`export`): `index.html` підключає лише
точку входу `<script type="module" src="js/app.js">`, а решта залежностей підтягуються
через `import`. ES-модулі підтримуються Safari 11+ (отже й Safari 15); top-level await
не використовується. CDN-бібліотеки (MQTT.js, qrcodejs) лишаються класичними скриптами
і дають глобали `mqtt` / `QRCode`.

Стилі організовано так само: `css/styles.css` — **вхідна точка**, що лише підключає
логічні партіали через `@import` (мірою росту проєкту простіше тримати кожну зону в
окремому файлі). Жодних inline-стилів у розмітці; усі кольори — через CSS-змінні в
`base.css` (теми перемикаються заміною `[data-theme]`).

> **Важливо:** ES-модулі **не працюють через `file://`** (CORS) — застосунок треба
> відкривати лише через `http://localhost` або HTTPS (див. локальний запуск нижче).

Шрифт — **[Andika](https://software.sil.org/andika/)** (SIL International), створений для
високої читабельності з повною підтримкою кирилиці; підключається з Google Fonts із
`display=swap` (системний sans-serif як fallback).

### Протокол повідомлень (тема `velyki/<room>`)

Payload кожного повідомлення — `base64url(iv).base64url(ciphertext)` (AES-GCM над JSON):

| Повідомлення | Коли | retain |
|---|---|---|
| `{ "type": "live", "text": "…" }` | при кожній зміні поля (debounce) | так |
| `{ "type": "commit", "text": "…" }` | натиснуто Enter — рядок іде в історію | ні |
| `{ "type": "settings", "size", "displayTheme", "mode", "speed" }` | Sender керує показом на Display | так |

Display тримає історію (останні ~10 рядків) у пам'яті; `retain` на `live`/`settings` дає
останній стан тому, хто приєднався пізніше.

Окремо від теми кімнати кожна роль публікує **presence**-маркер у
`velyki/<room>/presence/<role>` (retained) і стежить за партнером. Last Will та закриття
вкладки очищають маркер → статус показує «очікування пристрою…», коли пари ще немає.

### Як розширювати

- **Новий екран/режим** — додати секцію в `index.html`, створити `js/<name>.js` з
  `export function init() { … }`, заімпортувати його в `js/app.js` і додати гілку в `boot()`.
- **Інший транспорт** (власний брокер чи Firebase у v2) — змінити лише `js/mqtt-client.js`,
  зберігши інтерфейс `connect / encode / decode`.
- **Налаштування** — усі «магічні» числа, рядки та значення за замовчуванням
  централізовано в `js/config.js`.

## Технічні нотатки

- Приймач — **iPad Air 2 / Safari 15**: ванільний JS у вигляді ES-модулів (без бандлера,
  без top-level await). Через CORS-обмеження модулів — лише `http(s)`, не `file://`.
- Українська вводиться **системною клавіатурою** (Gboard / голос); Web Speech API не використовується.
- CDN: [MQTT.js](https://unpkg.com/mqtt/dist/mqtt.min.js), [qrcodejs](https://github.com/davidshimjs/qrcodejs).
